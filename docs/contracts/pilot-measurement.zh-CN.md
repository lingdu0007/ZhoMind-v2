# Pilot 测量契约

Status: Ticket 29 的规范性测量边界；不是真实验收报告。

## 权威与身份

测量仍通过鉴权产品路径进行。管理员接口
`GET /api/v1/operations/measurement-snapshot` 仅返回聊天使用的同一个
Authorized Retrieval Candidate Pool 在排序前的指纹和计数，同时绑定当前已批准
路由、准入配置、检索策略、证据包络、产品修订、部署、主机可见的 CPU/内存
及单工作进程配置。主机数据描述操作系统可见资源，不代表独立验证的容器配额。

`MeasurementBinding` 包含这些身份、语料与合格块数、并发、主机类别、带时区的
精确起止时间，以及明确的 `local_deterministic` 或 `controlled_live` 模式。
它还包含精确已准入 `(entry, editorial revision)` 集合的哈希。
缺少活动路由或产品修订时，不能构造完整工作负载绑定。命令行声明必须在请求
套件或 bundle 运行前后与服务器快照一致。任一绑定值改变都会形成不同指纹；
所有必需快照字段均须验证；响应不完整时拒绝继续。
其他绑定或半开观察窗口之外的样本被拒绝。快照不激活路由、不发布 Candidate，
也不改变答案资格。

管理员接口 `GET /api/v1/operations/requests/{request_id}` 读取唯一且未过期的
聊天 Operational Event。缺失、重复、过期或非聊天观测均不可用。该接口从不
读取会话；新旧数据均服从现有净化规则和独立保留策略。计时使用现有事件维度，
无需数据库迁移。

## 测量与报告

版本化配置声明八名不同的已准入 Knowledge User、两个执行位置、两个排队位置、
每成员各一个位置、一个工作进程、50 个活跃条目和至多 10,000 个合格块。
运行器通过鉴权 SSE 发出 40 次 c1、40 次 c2 和十轮四请求突发。成员计数依据
服务器当前身份，而非 bearer 字符串数量。每轮突发必须实际观察到同时两执行、
两排队；四条响应或各自历史排队状态不足以证明。

准入确认时间取首个准入身份或 queued/running 帧。有意义的处理时间取首个
running/retrieval/generating/persistence 帧。实际内容时间取首个非空 content
帧，不取响应头、进度帧或 Generation Evidence Preview。闭合时间要求唯一且
一致的 completed execution/outcome 以及完整成帧的 `done: [DONE]`；
中断、重复或矛盾终止不能通过。这些是传输观察时间，不是模型 token 发出时间。
当前产品在答案验证和持久化后发送内容。
采集器还使用请求成员的凭据重载本次新会话。流中的 execution、答案身份、
outcome、完整内容、证据摘要和证据不足投影必须等于规范持久化消息。采集后
只保留哈希与计时；管理员不执行这种私有重载。

排队、检索、提供方和持久化耗时来自精确请求的管理员 Operational Event。
每次提供方尝试的耗时分别保留，提供方阶段必须包含全部尝试。应用可控耗时为
客户端总耗时减去提供方阶段，因此包含排队、应用工作和传输开销，不是独立 CPU
测量。关键维度缺失使目标不可用，而不是记零；生产者对明确未执行的聊天阶段
显式记录零。

所有有效、已鉴权、已准入请求保留在测量总体中，包括闭合的证据不足、非知识库
回复和 Generation Unavailable。无效、未授权、取消、限流与拒绝请求分别统计。
已准入但失败的执行没有闭合结果，导致闭合证据不完整，不能删除它来改善百分位。
内容、问题正文、凭据和任意原始错误不是报告字段。

报告保留逐值、数量和最大值。合格样本达到 20 个时，增加 nearest-rank P50、
P95 与观察性 P99。P99 仅供观察，不是独立接受的服务目标。缺失样本、部分轮次、
不足样本窗口不能宣称百分位达标。准入确认 P95 至多 1,000 ms，处理状态 P95
至多 2,000 ms，c2 闭合结果 P95 至多 30,000 ms。每个已准入突发请求必须在
包含排队和完整提供方路由后于 60,000 ms 内闭合。

`measure_bundle` 导入明确提供的已审核 manifest，再显式派发每个新任务，
从不发布。十条目和五十条目运行保留逐项哈希、尝试、冻结输入、embedding
配置哈希、实际执行时间和 Candidate 块数。旧完成任务或 no-op 不算重建。
部分完成、取消、失败、被替代或重试的工作不构成无失败批次通过。十项预算为
三十分钟，五十项为六十分钟；单项 Candidate 执行的 P95 目标为五分钟，
同样受最低样本数量规则约束。
构建观测保留实际起止时间，并核验运行和任务时间均位于绑定窗口。
五十条目重建必须使用 `replace` 操作，精确对应快照中的不可变条目/修订集合，
不能使用五十个新条目或不同修订。

## 可用性与决策

`collect_probe` 检查健康状态，并在要求时通过鉴权产品路径执行声明的净化知识
问题。普通寒暄不能满足知识路径探针。有效的 Evidence-Gated Answer 或
Generation Unavailable 算产品可用，后者仍是路由失败。不会抽样私有生产会话。

可用性聚合要求明确声明、互不重叠、按分钟对齐的核心使用时间表，覆盖精确
28 天绑定的全部四周。每分钟需要一次健康观测，以及不超过五分钟前的产品观测。
缺失分钟仍留在分母，覆盖缺失使验收不可用。绑定外、观察截止时间后或同一分钟
重复的探针输入被拒绝。

评估者的 `TriggerObservation` 绑定独立保留的证据哈希与精确测量条件。
`values` 通常为毫秒耗时，但排队饱和使用滚动一周中不同的 0..6 日偏移；
提供方不可用使用该周内发生时刻的偏移；路由成功使用 `(successful, 20)`；
可用性使用 `(available, expected)`。连续百分位值要求匹配的样本数均至少
20，并且证据窗口完整且连续。`complete_window` 是评估者证明，不是服务器
授权标志，也不是日历时间已流逝的证明。

决策评估覆盖全部 KB-SL-004 触发：80% 余量或更早检索失败；连续正常/提供方
三十秒 P95 未达标；两个容量相关六十秒超时；七天内三天队列饱和；七天内两次
提供方导致不可用；低于 95% 的路由成功；影响真实工作三十分钟的提供方中断；
两次十条目 bundle 超时；一次五十条目重建超时；四周可用性低于 99%；
一次四小时重建恢复超时；两次十五分钟普通重启超时。它产生无内容的 At Risk
记录，包含证据、负责人哈希、必需动作和七天内的复核期限；允许的处置为修复、
收窄承诺、重新验收或暂停。

这些记录属于评估产物，不自动修改 Delivery Acceptance 状态。负责的管理员/
评估者必须保留每周处置，并向现有受影响的 Delivery Acceptance 追加状态事件。
产物不能授予发布、启用 fallback、撤回有效内容或自动恢复验收。
请求和构建运行器将实际报告直接交给 `assess_reports`。它重新验证原始样本/
构建观测并计算指标，不信任已有判定标志。显式历史报告用于连续窗口与重复
bundle 触发。条件身份或并发不同的记录分组处理，重复证据被拒绝。
派生决策保留可计算哈希的 `evidence` 对象，包含精确验证过的无内容来源观测
与聚合输入；其规范 SHA-256 等于 `evidence_sha256`，不包含决策自身。
自动容量归因要求请求实际排队、总耗时超过六十秒，且扣除实测排队等待后
能够满足该预算。其他慢请求仍是不达标结果，但不会被推断为容量原因。

## 执行与剩余义务

在 `backend` 运行 `uv run python -m app.operations.pilot_runner --help`。
提供 `--base-url`、`--binding`、`--output` 和明确的 `--commissioned`。
任务类型为 `requests`、`ten_item_bundle`、`fifty_entry_rebuild` 与 `probe`。
可重复传入 `--history-report`，加入精确的旧请求/构建产物。`--trigger-file`
接受带证据的评估者观测，用于另行测量的可用性、恢复和真实工作中断事实；
这不会执行恢复，也不会制造缺失的日历证据。
请求/探针使用私有 `--question-file`，bundle 任务使用已批准的 `--bundle-file`。
令牌只从 `PILOT_ADMIN_TOKEN` 与 `PILOT_MEMBER_1_TOKEN` 至
`PILOT_MEMBER_8_TOKEN` 读取，不进入命令行参数或报告。CLI 禁用重定向及代理
继承，真实受控目标要求 HTTPS，并创建仅文件所有者可读写的新输出，不覆盖
历史证据。

`probe` 命令只执行一次观测，不是四周调度器。获得委托的运维人员必须每分钟
调用，保留去身份化观测与声明的核心时间表，并在完整窗口结束后聚合。
实际受控负载、批准的真实语料/构建/索引、提供方成功、连续监测和每周状态处置
证据仍须另行保留。普通重启与干净重建恢复的执行仍由 Ticket 30 负责。

本地报告始终保留 `live_acceptance=false`，没有命令独立激活 Pilot baseline。
确定性 HTTP 测试、模拟构建传输、合成四周向量和历史提供方烟测都不是真实
Pilot 容量、索引、可用性或部署验收。缺少这些必需观测或处置时，
Ticket 29 必须保持非终态。
