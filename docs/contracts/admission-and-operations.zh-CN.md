# 准入与运维

状态：规范；Ticket 28，KB-SO-004/005、KB-SL-001，以及 KB-RL-003、
KB-UX-002、KB-RA-007 的运维部分。ADR 0009 记录本决策。

## 准入

`pilot_admission/v1` 版本 1 在单个 API 进程内最多允许两个执行中、两个
排队中的问题。每位已认证成员最多各占一个位置，包括维护诊断请求。
配置公开这些边界、30 秒排队超时和规范 SHA-256 `configuration:` 标识。
运维快照只包含聚合计数，不包含成员或会话标识。

成功、失败、超时或取消都会且只会释放一次预留位置。
超时期限在入队时固定；晋升前在准入锁内裁决过期，即使等待任务延迟唤醒也不例外。
容量可用时，最早且符合资格的排队成员开始执行；
已经执行中的成员不能再占第二个执行位置。
`CHAT_MEMBER_LIMIT` 或 `CHAT_QUEUE_FULL` 是私有执行准入之前可重试的限流拒绝，
不创建虚构的已完成回答。浏览器创建会话使用随机 UUID，而非时钟标识。

获准请求在等待位置前提交排队中的私有执行。
SSE 展示等待或位置、预留回答标识、开始及保留的终态执行。
普通 HTTP 等待同一保留结果。排队请求开始前重新核实持久化成员仍为活跃状态。
`CHAT_QUEUE_TIMEOUT` 是可重试的失败执行，没有已完成结果；
所有者历史可见其标识与失败。排队和过载永不表示 Insufficient Evidence。
既有所有者、条件、冻结证据、生成路由捕获和交付屏障仍为权威。

## 构建优先级与恢复

存在交互工作时，Candidate 工作在领取新任务前等待。
已领取的构建在协作阶段边界让出资源，等待时提交事务，
续租其精确 attempt，并在继续前重新核实权威。
不抢占已经开始的外部调用。既有单 worker 边界、取消、派生数据清理
与发布分离保持不变。

开始服务请求前，启动流程将保留的 queued/running Answer Execution
协调为失败的 `ANSWER_EXECUTION_INTERRUPTED` 终态。
协调可重复执行且不会重放 provider。既有 Candidate 启动恢复保留已派发的
排队工作，并通过租约和清理协议协调被中断的 attempt。
重试仍是需要核验不可变输入的显式操作；重启不赋予发布权威。

## 非内容事件

新增 `20260912_0028` 迁移添加可空运维维度，不重写已有事件。
写入端和管理员读取端都净化新旧值：

- 请求标识为规范 UUIDv4 或 `unknown-request`；路径类别为注册的方法及路径模板
  加响应状态类别，绝不是原始 URL。
- 执行状态与结果采用封闭的 Answer Execution 词汇。
  计数和阶段耗时是非负整数，不接受布尔值或文字。
  阶段为 queue、application、retrieval、provider、persistence、stream。
- Gate 结果为 passed/rejected/unavailable。Provider 路由只保留规范的
  路由、配置、哈希标识，有界 attempt 计数、耗时及封闭回退结果，
  不保留 provider 标签或异常正文。
- 生效保留策略和准入配置使用哈希标识。未知错误文字归一为
  `APPLICATION_FAILED`。Provider、检索、持久化、流、队列与应用失败具有不同类别。
  生成路由中的 `application_failure` 仍属于应用失败。
  无效的旧总耗时投影为空值，不投影内容或虚构测量值。
- 问题、回答、摘录、正文、凭据、令牌、任意标签及未知字段均被排除，
  即使被注入允许的字段也不例外。

事件仍属于[试点安全与保留](pilot-safety-retention.zh-CN.md)规定的独立
默认 30 天保留类别，不属于会话存储。删除会话不能删除独立保留的事件。
既有定时清理和版本化策略变更权威继续适用。

## 管理员界面与证据

仅管理员可访问的 `/operations` 展示聚合准入、配置、有界近期耗时、
规范化失败、路由结果与恢复链接。计数包含 Candidate 和旧构建任务。
受支持重试动作指向已有的权限核验操作，不需要访问私有会话。
Knowledge User 不能打开此界面。

本地已认证 HTTP/SSE/历史、浏览器与迁移测试证明有界的确定性行为，
不证明持续负载延迟、多进程调度、真实 provider、Milvus、PostgreSQL 部署、
网络暴露或生产验收。Ticket 29 负责带工作负载条件的延迟测量；
本契约不作未经测量的延迟保证。
