# 知识反馈与维护

状态：规范性契约

Ticket 27 实施 KB-FB-001 至 KB-FB-006，以及 KB-UX-007、KB-SO-003 中的反馈部分。
本契约扩展[规范化权威](canonical-product-contracts.zh-CN.md)与
[Pilot 保留策略](pilot-safety-retention.zh-CN.md)，不授予发布、Provider 激活、
部署或路线图实施权限。

## 明确反馈

受支持与证据不足的已完成结果都提供四种选择：
`helpful`、`insufficient_evidence`、`outdated`、`out_of_scope`。
可选说明限制为 500 个字符，支持编辑、预览、取消和明确确认。选择选项、
导航及其他被动行为不创建信号。“有帮助”通常只作为采用信号，不自动创建工作项。

保留的原始信封绑定提交成员、精确提交时间、本人拥有的持久化回答与 Answer
Execution、已完成结果、精确发布版本、受影响条目或缺口上下文、所选类别及确认的说明。
默认不复制问题、回答、来源摘录或会话。同一成员、回答和范围的相同重试返回已保留
信号；冲突提交不静默覆盖它。

本人删除及默认 180 天过期会切断所有原始信号引用。信号或引用仍存留时，删除与清理
不得报告成功。独立验证的非个人决策可以保留。任何管理员权限都不授予对底层
Private Conversation Record 的访问。
反馈删除、过期清理和维护引用写入都先取得共享保留注册锁，再锁定信号行。写入锁失败
不能报告修改成功。创建在隔离校验后重新核对保留信号资格，合并在提交决策前重新核对；
两者同时检查过期时间与当前策略的年龄上限。校验期间到期的反馈不能授权新的维护项、
修订或信号引用。

## 责任与决策

System Administrator 指派维护责任，被指派的活跃成员明确接任。负责的 Maintainer
创建、合并、分诊、诊断并批准 Finding；明确命名的活跃 Work Owner 执行所分配的工作。
命令由当前持久化权威授权，不依赖客户端角色标记或旧复核分类。
指派读取与接任重试校验规范化记录的身份、类别、状态、封闭字段和管理员来源。已接任
责任必须对应且仅对应一条由该成员记录、满足封闭结构的接任事件。重复或畸形事件
不能授予权限，也不能产生成功接任回执。

每个持久维护项有且只有一个分类、P0-P3 严重性、处置、影响范围、负责的 Maintainer
和 Work Owner，并保留去标识化的已验证模式与结果链接。七种分类为 `confirmation`、
`content-integrity`、`source-freshness`、`coverage-gap`、
`retrieval-answer-behavior`、`product-privacy-operations`、`scope-roadmap`。
`needs-reproduction` 是处置，不是第八种分类。

`coverage_position` 是受控主题类别，不能替代具体影响范围。创建时，服务端保留
`affected_scope`：条目反馈绑定实际规范发布版本与编辑修订；缺口反馈只保留封闭的
证据不足原因和 Query Condition Set 标识，不保留问题正文、条件值或私有执行 ID。
合并反馈时追加去重后的目标，不能移除先前范围。即使尚未复现，原始反馈删除或过期
也不能抹掉这些非个人技术目标。符合资格的路线图候选快照保留相同范围，并与来源
维护决策核验。维护详情和路线图详情在原始反馈移除后仍展示该范围。

规范化快照和只追加事件决定 `open`、`triaged`、`in_progress`、`resolved`、
`deferred`、`closed_confirmation` 状态。命令绑定预期修订。未知字段、格式错误或
缺失的权威、矛盾历史、过时命令必须 fail closed。浏览器标签变化不能建立终态或结果。
事项读取在负责人授权前校验权威记录类别、维护身份类型与值，以及封闭负责人字段。
负责人缺失或畸形不能变成服务端异常，不相关的记录类别不能仅凭 schema 成为维护
权威。列表发现不能绕过相同的严格事项投影。

原始信封及可选说明只保留在可删除的信号存储中，不复制到不可变条目事件、Finding、
路线图候选或审计。产物既要有合法结构，也要有对应的父级资格决策；schema 名称本身
不是权威。

## 停用与处置

每个 P0/P1 事项立即引入 System Administrator，并暂停独立验证的最小 Acceptance
Blocking Scope。证据必须绑定受影响范围和精确验收状态事件，不能借用无关的历史停用。
条目版本级隔离逐条核对所选保留信号的受影响条目，以及其真实执行绑定的规范化发布版本。
未绑定条目的缺口、其他条目或其他条目的发布版本不能借用该停用。共享隐私故障不能
为不相关的维护分类建立隔离依据。

未解决 P0/P1 事项的规范化历史是实际的普通回答阻断，不只是验收记录上的标签。
检索排除精确的受影响条目或发布版本；collection 阻断只适用于本知识库的规范化
collection，部署阻断必须匹配配置中的部署身份。其他 collection、无关部署或仅针对
公开主张的暂停，不能证明当前回答范围已遏制。保留的阻断权威不完整时拒绝放行。
普通回答提交在共享的维护／保留写入锁下核对同一阻断，因此生成期间提交的阻断会
阻止成功回答持久化或返回。HTTP 与 SSE 保留相同的失败执行；SSE 结束标记不代表
已完成的 Answer Execution Outcome。

已授权 Work Owner 的明确复现或批准场景重放，可以使用只针对本事项的请求级验证
上下文。它绑定当前维护修订、责任人、精确阻断范围和合格的暂停验收事件，并重新
核对 Work Owner 与管理员仍有效。它不移除其他事项的阻断，不放宽来源／编辑资格，
也不授予 Provider 访问权；路由暂停时仍需要既有独立 Provider 调用授权。
fixture／重放保留与父决策事件绑定的封闭遏制验证凭据。普通聊天不能提交该上下文。
仅修复来源不会重新开放普通回答；阻断持续到有合格证据的解决决策。

合并在写入引用前，对传入反馈执行相同的隔离校验。当前阻断范围与停用事件必须仍与
维护决策一致。未绑定缺口、不匹配的发布版本或已被取代的停用证据，不能通过复用既有
事项加入维护；拒绝时不改变修订号和保留反馈引用。
P0/P1 不得等待例行评审，也不得延期进入路线图。每个检索回答类或产品隐私运维类事项，
即使是 P2/P3，也需要管理员参与。

P2 来源时效问题只有在没有已知矛盾、适用条件仍明确时，才可使用既有七天宽限。
P3 展示问题可留在有负责人的队列中。这两者都不放宽高严重性停用要求。
已接任的条目 Maintainer 针对当前发布版本、精确当前编辑修订及其中声明的时效触发条件，
明确请求来源复核。仅有维护责任不授予编辑权限。只有仍有证据资格的已发布修订可以
开始该复核，只追加事件记录原始复核时间。相同重试不重新开始七天计时，变化后的
修订或发布版本、未声明触发条件均被拒绝。整个宽限期间仍由既有来源丢失与完整性
排除规则决定证据资格。
P2 Work Owner 工作区可对保留反馈的条目目标明确登记复核。发布版本、触发条件选项与
首次复核时间来自该成员有权读取的编辑投影，不要求用户填写自造发布身份。加载或
选择目标不创建复核，刷新及重复确认保留原始复核时间。
复核读取、重试及当前或历史修订的证据资格使用相同的保留事件校验。它核对封闭字段、
精确发布修订与已声明触发条件、维护人接任事件与操作者、角色、生命周期迁移，以及
带时区且与事件时间相等的开始时间。重复或畸形事件不能建立宽限，也不能投影注入字段；
仅改写时间载荷不能延长复核计时。

处置链接到真实权威条目修订、来源变更、Boundary Query、检索或产品实验、产品修复、
事故处理或可追责延期。维护不能绕过编辑评审，不能让实质修改条目的人批准该修订。
恢复高严重性范围需要适用且已通过验收的修复或重新验收证据。
高严重性来源修复需提供另一份有效的 Delivery Acceptance Record，处于相同验收阶段
和部署，并覆盖被隔离身份。验收记录的证据与原失败检查项的新通过证据都必须引用
本次实际成功修复重放。激活时间必须晚于隔离和重放；旧验收或不相关的新批准不能
授权结案。解决记录同时保留精确验收状态事件与验收记录标识。Maintainer 提交管理员
提供的验收标识，不因此获得管理员专属验收访问权限。

来源变更结案需要独立批准的过时来源 fixture、当前成功的受支持回答重放，以及精确的
已修复来源标识。结案记录有资格的来源状态事件，而不只是可变的来源标签。缺失、
无关或在重放后发生变化的来源证据不能授权结案。
内容修订结案需要独立批准的内容错误 fixture 及其保留的完整性复核标识、当前成功的
受支持重放，以及精确的修复编辑修订和发布产物。修复必须是同一条目经过单独批准的
实质修订，并仍有回答资格。其发布版本必须实际支持修复重放，且通过经过验证的同条目
发布后继链连接原缺陷版本；允许结案前经历多次已复核替换。发布服务的不可变权限
校验继续有效。缺少修复产物、旧修订或旧版本，以及重放后新增的完整性缺陷，均不能
建立解决状态。维护只记录修订与发布结果链接，不自行修订、批准、构建或发布修复。
coverage-work 的独立批准覆盖缺口场景若原本预期受支持回答，并在真正发布且有回答
资格的知识上重放通过，可以用 entry-revision 结果结案。至少一份支持发布必须不在
fixture 原有发布快照中。结案绑定精确支持发布及编辑修订，并验证当前发布权威与
回答资格。无关发布产物或仍然证据不足的回答不能关闭覆盖修复；这条路径不放松
内容错误修复独立要求的发布后继链。

每次结案必须覆盖维护项完整保留的影响范围，包括后续合并的目标。对于修复解决，提交的已批准
fixture 集合必须与成功重放的场景集合相符。每个 fixture 按维护事件修订独立确定
最新重放；后续失败会使该场景早先的成功结果失去资格。选择在检查所属 fixture 前，
先校验之前各重放的事件、操作者、记录、摘要及父级权威；缺失或损坏的最新结果不能
静默恢复旧成功结果的资格。多个场景可以共同完成完整
范围的关闭，但局部修复不能关闭整项。工作区展示已批准场景和最新结果，允许明确
选择本次关闭证据，并一起提交全部选中的场景、重放和修复产物。
P2/P3 直接确认则需要独立批准的确认 Findings，其 fixture 共同覆盖完整保留范围。
每份 fixture 的预期与实际观察都必须是有证据支持的回答；每个条目目标必须出现在
该场景实际使用的证据发布中，且关闭时发布仍为当前版本并具备证据资格。这条路径
不虚构修复重放。明确的 `confirmation_closed` 事件保留精确 Finding 结果链接；
普通迁移不能直接关闭尚未解决的工作。历史读取重新校验保留 Findings、fixture、
范围与链接，但不会因后来来源失效而追溯否定原本合法的关闭。工作区只有在确认范围
完整且已批准时才提供直接关闭入口；加载不关闭事项。
合格确认可从 `triaged` 或 `in_progress` 关闭；开始已分配的验证工作不会移除合法关闭路径。
对于内容工作，工作区根据选中的已批准场景及其成功重放提供明确的修复
确认。提交直接使用重放中的精确修订和发布标识，不要求用户凭空填写产物标识。历史
复现版本明确标示为复现时版本，与修复重放验证的发布版本分开。加载工作区不会结案；
关闭确认和已记录的结果链接在刷新后仍保留。
对于 P0/P1 内容、检索和产品修复，已批准场景成功重放后，负责的 Maintainer 可填写
单独的重新验收标识。结案命令同时提交该标识与精确修复产物，不以停用记录或 Provider
调用准入替代。空输入不能启用结案；旧的、已暂停或无关记录仍被既有范围、时间及
重放证据校验拒绝，工作状态不变。加载或填写字段不会提交。成功解决保留合格验收
事件，并在关闭确认后刷新仍可读。这不执行发布、部署或路由激活。
Provider 恢复证据绑定认证执行实际使用的路由、激活事件和已验证验收摘要。结案需要
已批准的故障 fixture、当前成功重放及匹配的路由与验收产物。对于普通严重性工作，重新激活会使先前修复
证据失效，仅保存未激活草稿则不会。维护验证上下文不复制 Provider 凭据或端点。
暂停活动路由所绑定的验收，也会关闭普通维护复现对该 Provider 的访问。由门禁关闭造成
的生成不可用结果，不是独立复现的 Provider 缺陷，不能据此创建已验证 fixture 或
Finding。仅验证连接不能替代经过冻结证据流程的修复场景。
当前 System Administrator 可以为维护项中仍活跃的普通成员 Work Owner 签发有界
验证授权。签发绑定精确的 P0/P1 产品或隐私维护修订、保留的 Query Condition Set、
当前发布版本、当前止损事件，以及通过既有完整 Provider 审批检查的独立活动路由
准入记录。相同授权内容返回同一份经过资格检查的不可变记录，重试不能替换畸形的
保留记录；读取仍受维护项当前成员权限约束。仅签发授权不调用 Provider、不激活
路由，也不构成成功修复重放或修复后的重新验收证据。
Work Owner 明确提交复现或已批准 fixture 的重放时，只能针对授权绑定的非个人
Provider 故障场景使用它。准入及最终确认重新核对当前责任、维护修订、保留条件、
发布版本、止损及完整路由准入摘要。请求级路由沿用普通检索、冻结证据、生成、
引用校验和回答持久化流程，不替换普通活动指针。验证上下文记录授权标识与摘要，
不虚构激活事件。保留 fixture 和重放的读取会校验授权，并将其精确维护修订、执行人
和场景绑定到记录事件。维护修订变化后需要重新授权。成功隔离重放是修复证据，
不是路由激活或高严重性重新验收，不能单独授权结案。
首次 Provider 复现的授权仍要求保留的信号。独立 Provider 故障 fixture 获得 Finding
批准后，修复授权改为记录精确的 `approved_fixture_identity`。签发和执行核验 Finding、
fixture 范围及精确场景，同时仍要求 Work Owner 当前拥有的输入。该授权只能重放这一
fixture，不能授权新的复现。因此原始反馈删除或过期既不会撤销合法修复证据，也不会
重新创建原始引用。未批准的 fixture 不能替代缺失反馈；当前止损、责任、发布版本和
路由准入检查仍是必需条件。
P0/P1 Provider 结案需要一份独立活动的修复验收，与原验收阶段和部署一致并覆盖止损
范围。其记录证据以及原先失败、现已通过的检查项都必须引用成功隔离重放；验收须晚于
止损和重放。当前活动路由必须是实际验证的路由，由参与该维护项的管理员在重放后
明确激活，并绑定修复验收，而非隔离调用准入记录。原调用准入也必须继续具备资格。
结案保留精确的修复验收状态事件和路由激活事件。未激活路由、无关激活，或仅在验收
其中一个层级引用重放，均不能建立解决状态。普通路由激活仍是既有管理员明确操作，
维护不会自行执行它。
高严重性 Provider 工作区将管理员签发与 Work Owner 执行分开。签发需要明确确认所列
路由、调用准入和 Query Condition Set；加载或编辑字段不会签发。Work Owner 明确加载
保留授权，只有维护项、修订、责任人及查询条件与所选复现或批准重放一致时才能选用。
刷新清空本地选用状态，旧维护修订的授权不能启用重放；每次签发成功后清空确认复选框。
Maintainer 结案提交单独输入的修复验收，不以调用准入替代。隔离重放将保留的准入标示
为调用准入，并单独展示验证授权，不将其显示为普通路由验收。服务器拒绝仍可见，不会将
工作显示为已解决；成功关闭确认后，刷新保留结果链接。
产品工作流修复需要独立批准的失败执行场景，以及当前仍有资格的受支持参照。结案产物
为该精确 fixture 与其当前成功的受支持修复重放，重放须携带与参照完全一致的发布版本。
已完成的 Provider 失败不能替代失败的产品执行；未修复重放或其他维护分类不能授权
产品修复结案。此有界验证不发布代码、不部署变更，也不替代适用的高严重性重新验收。

## 独立诊断

Work Owner 独立复现或验证非个人场景。合成 fixture 是有意共享的材料，不是自动复制
的私有会话。明确确认必须是真正的布尔值 `true`，不能由数字或文本转换得到。

保留信号携带由服务器计算的结构化条件记录摘要，与原始完整 Query Condition Set
标识分离。独立复现匹配该条件摘要，而不是包含原问题的标识。因此改写问题不要求复制
原问题，但改变声明条件不能借用该报告。缺失条件来源时拒绝操作。独立场景自己的完整
Query Condition Set 在认证复现与修复重放之间仍须精确一致。

不可变 fixture 只保留请求摘要和已验证类别事实，不保留 `replay_request`、问题正文、
条件值或私有回答标识。每个 fixture 还保留所选信号的封闭非个人影响范围，不保留原始
信号标识或信封；登记在执行后重新核对该范围。来源和内容目标必须与所选条目一致；
登记及每次读取都将保留范围与维护项及发布复核核验。即使原始反馈已删除，也不能以
另一条目的已验证缺陷替代被报告条目。每次重放由 Work Owner 明确选择自己仍保留的执行；运行前必须
核对其请求摘要和完整 Query Condition Set 与批准场景一致。缺失、他人、已删除或不同
输入均被拒绝。输入继续遵循普通私有会话保留规则。重新编写同一独立场景可以提供新的
匹配输入，但不会恢复已删除反馈或复制原报告。工作区刷新或切换场景后清空重放输入
选择；选择输入本身不运行任何操作。首次 Provider 签发以 Work Owner 自己保留的执行
核验申请的完整 Query Condition Set，只将结构化条件摘要与报告匹配；修复签发则绑定
已批准的独立 fixture。两条路径都不会把问题和私有执行标识返回给管理员或写入持久授权。

诊断核对 fixture 的精确 Query Condition Set 和当前 Published Knowledge Versions。
可重复的认证 fixture 绑定实际检索策略、期望结果、观察结果或独立执行状态，以及验证
结论。给历史执行填入当前策略，不构成对其实际执行策略的证明。

没有合格知识时进入覆盖工作；知识错误或过时时进入内容或来源工作。检索、条件丢失、
引用漂移、Provider 和产品诊断需要相应的独立验证证据；证据不足本身永远不能证明检索
缺陷。同一个预先声明的 fixture 可在处置后重放，不能观察结果后修改期望来制造修复成功。
发布版本存在本身不能证明内容错误。已接任的条目 Maintainer 必须针对精确当前发布修订
及其声明的一个来源，明确确认独立复核的矛盾或完整性缺陷。命令只保留封闭的类别事件，
不保留问题、回答、来源摘录或反馈描述。仅具有维护责任不能登记这项编辑复核。
该事件立即排除这项修订的新回答资格，包括仍处于时效宽限期间的情况，但不改变发布
指针。匹配重试保留原事件。当前与历史资格均校验事件的发布版本、来源、执行人、
已接任责任及事件结构。内容诊断在发布复核中绑定这项合格事件标识；Work Owner 仍须
独立登记认证场景，再由 Maintainer 单独批准 Finding。这项复核既不发布修复，也不
代替实质修订审批。
内容维护工作区从编辑投影读取允许选择的修订、来源和保留复核标识。加载、选择缺陷
和刷新均不提交。每次明确提交（包括重试）都需要单独勾选默认未选中的独立复核确认；
已有复核固定使用原来源和缺陷类别。
引用漂移诊断需要当前仍有资格的受支持参照、冻结证据，以及由既有引用校验器拒绝其
尝试的真实认证生成失败。Provider 超时不能证明引用漂移。保留的 fixture 只记录已验证
类别事实，不记录被拒绝的生成文本。引用修复只有在同一声明场景针对精确参照发布版本
成功重放后，才能关闭有界检索实验；未修复的重放不能结案。
检索遗漏诊断需要当前仍有资格的受支持参照、没有冻结证据的真实证据不足结果，以及
`no_eligible_published_evidence` 原因。选取证据后的生成失败不能证明检索遗漏。
已批准的检索遗漏场景使用同样的有界实验结案检查：当前成功的受支持重放必须携带
与参照完全一致的发布版本标识。
条件丢失验证使用执行契约在调用 Provider 前的真实比对：结构有效的生成输入仅在
冻结 Query Condition Set 上发生变化。该执行保持 `failed`，没有已完成结果，
也不声称 Provider 已接收变化后的输入。超时或其他畸形、变化的输入不能证明条件丢失。
维护只保留已验证差异的类别事实，并要求当前仍有资格的受支持参照。修复使用同一
声明场景，以及精确参照发布版本的实验结案检查。

当前发布标识来自权威发布指针，而不是知识地图可见性或最新编辑草稿。来源诊断读取
精确发布修订的来源，并绑定当前有资格的来源状态事件标识。后续草稿不能静默替代
正在诊断的发布版本。来源发生变更会使之前的诊断或修复证据失效，即使可见的可用性
状态随后又改回原值。
来源快照还绑定完整的保留事件标识集合。同时间的含糊来源状态事件不能通过随机标识
排序建立当前维护权威。
历史受支持参照还必须针对精确发布版本及来源事件重新核验当前证据资格。不能仅因
版本仍处于发布状态，就将不可用来源造成的问题改判为检索遗漏。

修复重放使用已批准的独立 fixture，并单独记录不可变结果。场景登记与重放事件绑定
完整产物摘要；schema 标签或被改写后内部一致的结果不能建立验证权威。解决维护项
既需要合格的关闭产物，也需要当前且成功的重放。失败、过时或未经资格确认的重放
不能授权关闭。
后续复现不会撤销先前已批准的 fixture，也不会让其历史重放变得不可读。授权精确登记
场景重放的是已批准 Finding，而不是最新 fixture 指针。重复证据不能替换原批准预期，
也不能授权第二个 fixture。工作区分别展示当前诊断与已批准修复场景；解决控件将
所选场景绑定到其自身成功重放。

批准事件在维护历史中绑定完整 Finding 摘要。读取、重放授权和路线图资格使用相同的
封闭字段、批准摘要及独立登记 fixture 校验；被改写的字段不能成为保留证据，也不能
经由读取投影泄露。
Finding 身份同时绑定 fixture 的具体范围、发布与参照复核，以及执行验证指纹。
验证另一目标不能返回首个目标的 Finding；相同目标的重复证据仍保留原批准。
路线图独立样本计数使用的执行指纹不变，仅目标不同不能制造独立验证样本。

Maintainer 批准独立验证的 Finding，而不是自己未经验证的断言。Finding 不包含原始
问题、回答、会话、提交身份、精确提交时间或可选说明。原始信号移除后，其规范化模式、
验证方法与结果、影响范围及有界行动链接可以保留。

## 节奏与路线图

普通反馈在七天内分诊。每周检查未结工作及路线图资格，每月检查知识健康和延期，
每季度记录抽样验收。评审证据绑定当前工作修订与责任人。一位 Maintainer 的评审不会
静默履行另一位 Maintainer 的责任。逾期工作保持可见。

评审提交绑定所显示上下文的摘要。保留快照包含本人负责的未结工作修订、当前延期修订
与知识健康。发布修订标识必须与当前编辑修订及其可用性分开记录。季度抽样绑定每份
有效验收记录的精确 `checks_verified` 事件、已验收范围、核验时间与核验人，以及完整的
逐项结果和核验证据。核验必须发生在当前 UTC 自然季度内，不能使用未来时间。
没有本季度核验的历史 Active 记录不能成为新的季度样本。既有 Delivery Acceptance
核验是权威来源；维护模块不能仅凭时间戳制造通过的运行，也不复制其执行流程。
沿用检查保留独立的结果类别和证据，不得改称本次新通过。上下文变化后必须重新核对；重复或格式错误
的记录事件不能建立评审完成状态。已由另一位负责的 Maintainer 分诊的信号，不继续
计作未分诊。

路线图资格要求滚动 30 天内至少三个不同 Answer Execution 的结果，或两份独立
Validated Finding。不同执行可以有相同的已完成结果类别。成员身份永远不是聚合键；
重复信号或修改期望结果不能生成独立证据。明确的 `scope-roadmap` 可以直接形成
可追责延期。P0/P1 不能使用任何资格路径延期。

候选只保留非个人模式、影响范围、期望目标、有界工作无法闭合的原因、当前范围边界、
负责人、评审日期和维护决策链接。负责人每月选择创建独立 Wayfinder map，或以负责人、
理由、日期续期，或关闭候选。创建 map 不等于委派实施。责任成功转交后返回该命令回执；
后续读取按新权威授权。

候选发现遵循当前负责人或原始维护责任。资格决策绑定初始候选摘要，月度历史校验
操作者、连续修订及合法状态迁移。探索图必须匹配月度决策实际创建的精确标识和摘要；
仅带 schema 标签或内容被替换的产物必须拒绝。
