# ADR 0009：有界交互准入与非内容运维

状态：已接受

日期：2026-09-12

日常可用 Pilot 将历史的五个并发问题限制替换为两个执行中、两个排队中，
每位成员最多各占一个位置。进程内准入门控与持久化的私有 Answer Execution
事件将有界调度和保留的用户结果分开。溢出可重试；重启将被中断的执行闭合，
不重放 provider 工作。本决策只取代早期单机发布决策中的并发部分，
不改变成员数、发布数量、上传大小或构建 worker 数量限制。

受支持的 Pilot 使用一个 API 进程及其已有 Candidate worker。
交互工作已获准入时，Candidate 工作在阶段边界协作让出资源；
不承诺抢占已经开始的外部调用。多个 API 进程在获得验收前必须引入共享准入权威。
阶段耗时是证据，不是后续 Ticket 29 延迟目标已达成的证明。

详细规范见[准入与运维契约](../contracts/admission-and-operations.zh-CN.md)。
运维只保留有类型、封闭的非内容维度，不提供对话访问。
ADR 0007 的独立保留策略仍为权威。队列恢复不发布、不重新检索，
也不推断 Insufficient Evidence。
