# ADR 0006：按版本限定的发布撤回

状态：已接受

日期：2026-09-08

替代范围：仅替代 ADR 0004 中 completion 时对 tombstone 做脱敏后继续完成的规则。
将 ADR 0002 的有限管理员发布权限扩展到对精确当前 Published Knowledge Version 的显式撤回。

## 背景

文档删除不能证明发布撤回的操作者、原因、版本或影响范围。按整个文档脱敏历史，
还会混淆已被替换的前代与被撤回的当前版本。后续修订正在审稿，不能阻止对仍在发布的
版本实施紧急隔离。

## 决策

- 只有服务器确认仍活跃的管理员可以撤回精确当前发布版本。追加
  `publication_withdrawal/v1` 前重新校验不可变发布记录、运行时指针、条目、
  generation 和 configuration。保留原始事件标识、操作者、时间、有限原因和触发类型、
  条目版本影响范围及前代标识。重复请求重放原事件；修改原因或触发类型返回冲突。
- Published 和 Needs Re-review 版本可以撤回。管理员证明已有当前发布版本时，
  Editorial Review 和 Candidate Build 也可以终止为 Withdrawn，因为它们可能描述
  尚未发布的后续修订。这些转换不授权草稿删除，也不允许撤回从未发布的条目。
- 隔离动作与发布及回答最终持久化串行化。在历史或向量清理之前，持久化撤回事件、
  检索 tombstone、后续任务失效和受影响验收暂停。清理失败不能回滚已生效的撤回。
  Candidate 完成流程与撤回一样，先取得 canonical authority 锁，再取得 job 锁，
  并在锁内重新校验 lease 与不可变输入；等待撤回持有的权威事实栅栏时不能占有 job 锁。
- 用只追加的 `withdrawal_reconciliation/v1` 事件记录清理。显式重试重新校验每个
  冻结 generation 和 embedding fingerprint，清理派生数据，并仅解除已验证的任务
  清理义务。后端不可用时保留有限诊断和暂停、可重试的义务。重试和恢复均不修改
  发布指针，也不使已撤回内容重新获得资格。
  范围也包含 dense backfill 产生的精确运行时文档 generation 及已存 fingerprint，
  不只清理 Candidate 向量地址。backfill 写入前锁定并重新验证当前文档及撤回权限事实，
  恢复兼容 tombstone 投影不能重新生成这些派生数据。
  切换 fingerprint 前必须清理旧地址，才能覆盖 readiness 绑定。清理状态读取校验
  审计及范围绑定；仍有已知派生义务时，不能接受 completed 事件。
  每次运行时 backfill 写入前，先以只追加的 `runtime_dense_cleanup/v1` 记录持久化
  精确 publication、document、generation 和 fingerprint。提交后重新取得文档栅栏
  并检查撤回事实。响应丢失、readiness 提交失败和取消均保留这些地址。清理在与最终
  完成相同的事务中记录每个目标已验证的删除，因此重试不会丢失地址。
  运行时行缺失不能把已知规范发布版本降级为 legacy。清理还要求持久化的写入退出证明：
  Milvus 适配器等同步 upsert 退出后才传播已确认的取消。无法确认的取消或进程丢失
  继续保留 pending 地址，并使清理保持 suspended，直到能够证明写入已终止；
  删除请求返回本身不是该证明。
  后续 Candidate 遵守同一规则：每个已进入 indexing 的 attempt 必须具有精确的
  `candidate_writer_exit/v1` 证明，才能解除派生清理义务。取消确认本身不够。
  即使撤回已经使 lease 失效，或 worker 在启动外部写入前退出，也会记录退出证明。
  对此证明引入前已成功构建的 Candidate，精确的只追加完成事件与匹配的不可变
  Candidate 记录可共同证明对应 attempt 的 indexing 已返回。必须验证 attempt、
  冻结输入及完整地址和配置绑定，不能补造 worker-exit 事件。可变终态、失败或取消的
  attempt、缺失记录及矛盾事实均不能替代该证明。
  对 0018 之前的记录，只有输入加载器验证其精确旧格式并重算完整绑定后，才允许
  缺少 frozen-input hash。只在读取时归一化缺失哈希，保留原记录；已存在的错误哈希
  或现代记录缺失哈希仍然无效。
  运行时 backfill 还会记录目标登记后整个准备阶段中已知的未写入退出，包括锁定或
  chunk 读取失败。若目标登记事务失败且尚未写入，则不创建孤立的 settled 事件。
  启动恢复对已撤回条目使用相同门槛。显式清理及其 completed 投影重新检查全部
  受影响的未发布任务，而不只检查可变 cleanup-pending 标记仍为 true 的任务。
  可变 Candidate 索引缺失时，还通过不可变 publication、Candidate 和 build-generation
  绑定识别历史已发布任务。新 bundle 导入共用条目栅栏，即使持有保留的 approved export，
  已撤回条目也不能准入新的构建任务；no-op 和 proposed-withdrawal 记录不创建构建任务。
- 尚未完成的回答若发现冻结证据已撤回，必须失败，不能加上撤回标注后继续成为
  新的受支持回答。HTTP 和 SSE 投影保留的失败，不发送生成回答内容。
- 已完成私有回答保留 evidence-set、item、snapshot、citation 和 publication 标识。
  追加版本级脱敏事件，并在每次普通响应最终投影、历史或待发送流投影时关联权威撤回
  事实，即使此前脱敏写入失败或撤回在回答完成后才提交也如此。显示撤回通知，
  不显示 excerpt 或可作为当前证据打开的来源。
  不对前代历史作整批脱敏。
  所有投影校验完整撤回形状、审计绑定及不可变发布谱系。缺失或矛盾的事实必须
  fail closed，不能被解释为不受影响的来源或验收范围。
- 既有验收记录仍绑定原始范围。撤回会为受影响的 active 或 at-risk 记录追加暂停；
  投影还排除每个已撤回的绑定条目或版本，包括记录暂停后发生的新增撤回。
  无关记录仍保持 active。清理不等于重新验收，不能重新激活已撤回范围。
- 旧单项和批量文档删除入口拒绝已发布版本。未发布草稿删除仍是不同操作。

## 后果

撤回是持久隔离动作，不是物理删除发布谱系。不可变发布记录和原始已完成结果继续
保留，但用户投影被脱敏。无需新增数据库结构：规范化只追加事件及已有执行脱敏
事件流承载新增记录。

真实向量后端、PostgreSQL 并发、持久化栈恢复与部署验收仍是独立于确定性本地测试的
义务。本决策不激活提供方、检索策略、新保留政策或通用回滚界面。
